# 사람의 판단과 변경 처리

## 검토 자료

[검토 양식](../templates/REVIEW.md)을 사용한다. 읽을 수 있는 설명과 직접 확인할 결과물을 먼저 준비한다. 결정 요청에는 대상 버전, 선택할 사항, 추천 이유, 한계, 결정 후 작업 범위가 있어야 한다.

| 시점 | 사람이 볼 것 | 결정 |
| --- | --- | --- |
| C · 콘셉트 | 고객 과업, 제안 가치, 시나리오, 근거와 가설, 제외 범위 | 선택 / 수정 / 보류 |
| E · 경험 | 대표 화면, 실제 내용, 핵심 동작 시제품, 레퍼런스 해석, 기술 제약 | 유지 / 수정 / 범위 조정 |
| R · 공개 | 검수된 버전, 사용자 범위, 남은 위험, 운영·복구 방법 | 범위 내 공개 / 수정 / 보류 |
| 고객 실험 후 | 실제 사용·재사용·구매 증거, 표본과 기간, 불확실성 | 계속 / 개선 / 전환 / 중단 / 추가 관찰 |

C와 E를 같은 결과물로 충분히 판단할 수 있으면 함께 검토할 수 있다. 기존 사용자 지시로 이미 결정된 사항은 다시 묻지 않는다. 새 가설을 탐색하는 가역적 시제품은 검토 전에도 만들 수 있지만 확정안으로 기록하지 않는다.

## 기록 계약

결정은 다음 항목을 가진다.

- 결정 ID, 시점, 사용자 또는 확인 가능한 권한 주체
- 실제 발언이나 신뢰할 수 있는 원문 참조
- 검토한 파일·화면·커밋·콘텐츠 버전
- 선택과 이유, 포함·제외 범위
- 외부 행동의 대상·한도·허용 범위(해당할 때)
- 이 결정을 대체하는 후속 결정 ID

요청본·검토본·선택본을 구분한다. 검토 자료를 제출할 때 불변 커밋 또는 파일 복사본을 보존한다. 사람이 버전 A를 본 뒤 B로 수정했다면 A의 승인으로 B 전체가 승인됐다고 해석하지 않는다. 변경의 의미와 승인 범위에 따라 재검토 여부를 결정한다.

최신 제품 기록은 수정할 수 있지만 과거 결정과 원문은 덮어쓰지 않는다. 미완성 작업도 저장하고, 재시작할 때 실제 결과물과 마지막 결정을 읽는다. 실행 여부가 불확실한 외부 작업은 상태를 확인하기 전 재시도하지 않는다.

## 어떤 변경에 다시 판단이 필요한가

- 제품 대상·문제·핵심 경험 또는 선택한 디자인 방향을 바꾸는 경우
- 합의한 비용·일정·공개·데이터 이용 범위를 넘어서는 경우
- 사람의 선택이 없으면 해결할 수 없는 설계 충돌이나 중요한 운영 위험
- 승인한 전제가 실제 증거와 충돌하는 경우

명확한 오탈자, 승인 범위 안의 버그 수정, 테스트 재실행, 같은 방향의 구현 개선은 계속 진행한다. 사람의 선택은 구체적인 영향 부분에만 요청한다. 승인 대기 중에는 관련 작업만 멈추고 독립적인 준비는 진행한다. 무응답은 동의가 아니다.

## 검토와 고객 증거

제품 책임자의 선택은 고객 검증과 다르다. 디자인 승인은 수요·재사용·결제의 증거가 아니다. AI의 평가와 사람의 직접 사용 평가도 실제 고객 인터뷰·행동 관찰과 구분한다.

아크의 ready는 검토할 자료가 준비됐다는 의미다. 시스템이 사람을 대신해 승인 기록을 생성하지 않는다. 이 패키지는 지침이며 서버 권한 검사나 자동 승인 차단 장치를 구현하지 않는다.
