# v7 → v8 변경과 근거

## 확인한 출발점

tomob-system main의 37117cbb7fe095483a938df4aa785d4cfcf810f9에는 운영 설명용 index.html 한 개가 있었다. 이번 버전은 그 페이지를 보존하고, 메인 진입 지침과 실제 Claude Code 역할 정의를 추가한다. 다른 저장소나 사용자의 전역 설정에 있는 에이전트를 자동 교체하지 않는다.

[이전 안내 페이지](../archive/v7.html)는 참고 기록이다. 내부의 v6/v7 표기, 모델 배분, 고정 제작 규칙은 현재 운영 기준이 아니다.

## 유지·변경

| v7 | v8 |
| --- | --- |
| 앤의 순서 관리 | 의도·결정 이유·버전·다음 행동을 유지 |
| 시온·프레이·피어·에이미 | 다섯 책임 안에서 필요한 전문 관점으로 활용 |
| 브리프 필수 | 기존 브리프 재사용 또는 원문에서 초안 생성; 미정은 구분 |
| 모든 호출에 이미지 필수 | 해당 작업에 필요한 자료만 전달 |
| 고정 랜딩 섹션·CTA 수·폰트 금지 | 제품·과업·선택한 디자인에 따른 경험 기준 |
| 모든 인계 아크 검문 | 주요 인계·검토·공개 후보·근거 충돌에 집중 |
| 전 팀원 특정 모델 | 현재 세션 모델 상속 |
| 최종 제작 보고 | 고객·운영 증거를 다음 결정에 연결 |
| /start 등 명령어 설명 | 자연어 진입과 실제 역할 파일; 미설치 명령을 약속하지 않음 |

일정표·스프린트 예시·별도 오케스트레이터는 포함하지 않는다. 승인된 범위의 작업은 자율 진행하고, 바뀌는 결정에만 사람의 판단을 요청한다.

## ZEDER에서 가져온 원리

참고 스냅샷: sungeunstar/zeder_search의 630bbc1334af3c573aee8071609e477962464500. 기획 문서와 코드·변경 이력을 읽은 결과다. 고객 성과나 시각 품질 전체가 검증됐다는 뜻은 아니다.

1. **사용자에게 전문 작업을 떠넘기지 않기.** [UX.md](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/docs/UX.md)의 대화 우선·별도 작업 공간 원리를 의도 수집에 적용한다.
2. **콘셉트와 동작 연결.** [ATELIER.md](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/docs/ATELIER.md), [WORK-DIRECTOR.md](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/docs/WORK-DIRECTOR.md)의 요청→장인 동작→결과 확인처럼 대표 경험을 먼저 구현한다. 3D 공방이나 특정 스타일을 모든 제품에 적용하지 않는다.
3. **원문과 제안 분리.** [brief.js](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/public/brief.js)의 출처·상태·제출 당시 기록 보존을 제품 기록과 인계에 적용한다.
4. **판단을 결과에 연결.** [single-gate.js](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/public/single-gate.js)의 핵심 가설·실행·변경 이유를 검토 양식에 적용한다. 이 제품의 단일 마케팅 검토를 전체 개발의 승인 횟수로 복제하지 않는다. 최신 단일 검토 흐름과 이전 UX 문서의 다중 승인 설명은 구분한다.
5. **이미지와 구현 품질 구분.** [COAST-REVISION.md](https://github.com/sungeunstar/zeder_search/blob/630bbc1334af3c573aee8071609e477962464500/docs/COAST-REVISION.md)의 구현 한계를 참고해 어려운 장면을 조기에 검증한다.

## 안내 페이지의 디자인 결정

대상은 토모브 운영자이며 목적은 현재 운영 흐름과 해당 역할·양식을 빠르게 찾는 것이다. 기존 어두운 표면과 보라색 강조를 유지하고, 문서형 목차·작업 순서·역할 행·접히는 상세로 구성한다. 자료는 실제 역할 지침과 운영 계약만 사용하고 이미지나 성과 수치는 추가하지 않는다.

구조: index / 첫 화면에서 현재 운영 방식 설명 / 근거는 실제 문서 / 읽기와 탐색 중심 / 섹션 목차 / 역할·양식 열기.

Genesis 매개변수는 variance 2(안정된 문서 정렬), motion 1(기본 상태만), density 6(운영 문서의 비교·탐색)으로 정한다. 시스템 글꼴을 사용해 외부 폰트 의존을 없애고, 키보드 포커스와 320·375·768·1440 폭을 확인한다. 이 값은 이 안내 페이지에만 적용한다.
