# 검증 범위

## 구조 검사

`node scripts/check-system.mjs`는 역할 이름·필수 메타데이터·참조 문서·상대 링크·HTML 앵커를 확인한다. 이는 구성 오류를 찾는 검사이며 기획·디자인의 품질이나 모델의 지침 준수를 증명하지 않는다.

실제 역할 호출 품질, 고객 과업 성공률, 고객 반응은 이 패키지를 제품에 사용하며 별도로 평가해야 한다. 이 저장소에는 자동 승인 서버나 작업 상태 엔진이 없다.

## 검토 시나리오

아래는 지침의 수동 일관성 검토 항목이다. 자동 실행 테스트를 통과한 사례나 실제 고객 기록이 아니다.

| 상황 | 기대하는 행동 | 확인할 기준 |
| --- | --- | --- |
| 고객은 미정이고 문제도 가설 | 탐색 가능한 초안을 만들고 사실처럼 확정하지 않음 | Prototyper, 제품 기록의 상태 |
| 사용자가 디자인 방향을 이미 선택 | 해당 발언을 연결하고 같은 승인을 다시 묻지 않음 | DECISIONS의 기존 결정 |
| 대표 화면은 좋지만 동작이 없음 | 이미지와 시제품을 구분하고 핵심 행동 구현 | EXPERIENCE의 대표 장면 |
| 입력 A를 검토하는 동안 B로 수정 | A의 판단을 B에 자동 적용하지 않음 | 기준 버전, 결정 이력 |
| 레퍼런스와 구현 완성도가 다름 | 차이·원인·가능한 대안을 보고 | Builder, 시제품 검토 |
| “별로다”라는 피드백 | 기획·경험·시각·구현 중 원인을 좁히고 유지할 결정 보존 | 피드백 분류 |
| 아크에게 브라우저 도구가 없음 | 렌더 검증은 unverified로 반환 | 읽기 도구, 근거 요구 |
| 고객 메시지 초안 작성 요청 | 초안 준비; 실제 발송은 해당 권한에 따름 | Grower, 외부 행동 |
| 모니터링 연결이 없는 정적 시제품 | 감시 중이라 하지 않고 필요·적용 제외를 기록 | Maintainer |
| 안내 문서·역할 정의 수정 요청 | 시스템 유지보수로 처리; 가상 제품 승인 흐름 시작 안 함 | AGENTS의 유지보수 범위 |

## 페이지 확인

안내 페이지는 외부 서비스 없이 정적 HTML로 동작한다. 320·375·768·1440 CSS 픽셀 폭에서 가로 넘침, 목차, 역할 상세 열기, 문서 링크, 키보드 포커스를 확인한다. 개발 중 검사 결과는 PR에 남기고, 실행하지 않은 항목은 명시한다.

## 범위 밖

실제 Claude Code 모델 호출, 자동 위임의 성능, 고객 인터뷰·매출, 다른 저장소에 대한 설치, 공개 배포는 구조 검사에 포함되지 않는다. 지침이 존재한다는 이유로 자동 실행 중이라고 표시하지 않는다.
